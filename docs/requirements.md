# Требования BeeHealth

Пользователь системы — пасечник. Он регистрирует хозяйство и семьи, ведёт журнал наблюдений и отслеживает план профилактических мероприятий.

1. В разделе «Пасеки» можно добавлять и редактировать названия и местоположения, искать по обоим полям и удалять пасеки без зависимых ульев.
2. В «Ульях» можно выбрать пасеку, указать номер улья и найти его по пасеке или номеру. Номер уникален внутри пасеки.
3. В карточке семьи доступны улей, название, дата заселения и признак активности. В одном улье может быть только одна активная семья. Архивная семья остаётся в истории.
4. Журнал показывает семью, дату, состояние, заметки. Поиск работает по семье, состоянию и заметкам. Период включает обе границы.
5. Профилактика показывает тип, семью, плановую дату, статус, дату выполнения и номер связанного осмотра. Виды мероприятий редактируются отдельно.
6. Сводка считает активные семьи SQL-запросом с GROUP BY и включает пасеки с нулём семей. Она показывает историю осмотров, выполненную и запланированную профилактику. Для выполненной профилактики период учитывает дату выполнения, для планов — плановую дату.
7. Удаление требует подтверждения. Если существуют связанные записи, SQL Server сохраняет их и запрещает удаление родительской записи. При пустой выборке показывается сообщение.

## Бизнес-правила

- Осмотр разрешён в день заселения или позже. C# проверяет дату внутри транзакции с блокировкой записи семьи. Триггеры SQL защищают от прямого изменения осмотра и переноса даты заселения позже существующего осмотра.
- Статус «Выполнено» требует даты выполнения. У плана дата выполнения отсутствует. Правило проверяется сервисом и ограничением CHECK.
- При создании осмотра пользователь может выбрать выполненные мероприятия. Сначала вставляется осмотр, затем мероприятия с его номером. Все команды используют один объект SqlTransaction. При отказе последующей вставки вызывается Rollback. Составной FK гарантирует принадлежность осмотра и мероприятия одной семье.

## Структура

`MainWindow` отвечает за навигацию, таблицы и сводку. `RecordWindow` строит формы по описаниям полей из `Catalog`. `BeeService` выполняет бизнес-проверки и управляет транзакцией. `Database` выполняет запросы ADO.NET, освобождает подключения и передаёт пользовательские значения как параметры. Имена таблиц и столбцов берутся из фиксированных описаний.

В проект не входят ветеринарные рекомендации, уведомления, синхронизация с внешними сервисами и отдельные учётные роли.
